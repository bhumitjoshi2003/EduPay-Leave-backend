# Bhagavad Gita corpus extractor (Annie Besant, 1922, 4th edition)

One-time, offline data-preparation tooling. **Never invoked by the running application** —
the application never fetches scripture from the internet, at startup or otherwise.

## What this is

A deterministic (no LLM) pipeline that extracts the complete Bhagavad-Gita from Wikisource's
proofread transcription of Annie Besant's 1922 (4th edition) translation, backed by the scanned
`Bhagavad Gita - Annie Besant 4th edition.djvu`, and produces
`src/main/resources/wisdom/gita-besant-1922-4th-edition.json` — a reviewable static artifact in
the exact shape `WisdomVerseImportService.VerseImportRecord` expects.

## Source / license

- Work: *The Bhagavad-Gita*, translated by Annie Wood Besant, 4th edition (1922).
- Wikisource's own tag on the work: `{{translation-license|original={{PD-old}}|translation={{PD/US|1933}}}}`
  — original Sanskrit is public domain by age; the translation is public domain in the US
  (Besant died 1933; also pre-1929 US publication rule applies independently).
- Every record's `sourceUrl` points at the specific Wikisource `Page:` namespace page it came
  from (e.g. `.../Page:Bhagavad_Gita_-_Annie_Besant_4th_edition.djvu/28`), each one individually
  citable and marked with its Wikisource proofreading quality level.
- Do NOT use Vedabase, the BBT/Prabhupada "Bhagavad-Gita As It Is" translation (actively
  litigated copyrighted commentary), or any other translation to "fill gaps" in this one.

## Reproducing the extraction

```
./fetch_pages.sh          # fetches every DJVU page (ranges.txt) from Wikisource, 1 req/sec,
                           # with a descriptive User-Agent per Wikimedia's robot policy
python3 extract_besant_gita.py   # parses pages/*.txt deterministically, writes
                                  # gita_verses.json + anomalies.json in this directory
```

`extract_besant_gita.py` never asks an LLM to reconstruct Sanskrit, transliteration, or
translation text — it only does regex/brace-matched wikitext parsing. Transliteration is not
generated by this tool at all: `WisdomVerseImportService` derives it deterministically from the
Sanskrit via `DevanagariTransliterator` at import time, so it's never stored as an assumption
baked into the artifact.

## Known source anomalies (resolved, documented — not silently patched over)

- **Sanskrit split across a page-scan boundary**: handled by merging Wikisource's own `/s`/`/e`
  continuation-template pairs before treating a block as one verse.
- **Two verses (17.19 and 18.14) have a Sanskrit-embedded verse number that disagrees with the
  separately-typeset English `{{float right}}` marker** (off by one) — a genuine inconsistency
  in this edition/transcription. The Sanskrit-embedded number is treated as authoritative (it is
  intrinsic to the verse text, not a separately-typeset annotation); both numbers are recorded
  in `extraction-anomalies-report.json` for visibility.
- **One verse (18.47 in an earlier extraction pass) hit a footnote-stripping edge case** that
  would have corrupted its translation text; a final safety-net validation step in the parser
  detects any residual wikitext markup in a record and excludes it from the artifact rather than
  shipping malformed text — this instance was fixed and no longer needs exclusion, but the check
  remains in place for any future re-run.
- Chapter-closing colophons ("Thus, in the glorious Upanishads...") and the final benediction
  ("श्रीकृष्णार्पणमस्तु...") are recognized and excluded — they are not numbered verses in any
  edition.

## Result

701 verses across all 18 chapters (this edition's own numbering — see the extraction report for
the exact chapter-by-chapter breakdown; the commonly quoted "700" is an approximation that
varies by edition, not a fixed canonical count).
